# 文档中心使用指南

本站后台内置「文档 wiki」模块（后台 => 文档），用于集中查阅项目文档。本文说明其工作方式与维护规范。

## 工作原理

- 文档目录为项目根目录下的 `docs/`
- 由 `shared-admin` 子模块的 `SharedAdmin\Services\DocViewer` 自动扫描，**无需任何配置文件**
- 文档统一使用 Markdown（`.md`）编写

## 目录组织规则

DocViewer 按以下规则生成左侧导航：

- **根目录的 `.md` 文件**：归入「项目核心文档」分组
- **一级子目录**：每个子目录成为一个独立分组，分组名即目录名
- 以 `.` 开头的目录（如 `.obsidian`）自动忽略
- 更深层级的嵌套目录不会被扫描，请保持「根目录 + 一级子目录」两层结构

## 当前目录结构

```
docs/
├── ARCHITECTURE.md              # 项目架构（核心文档）
├── using-docs.md                # 本文（核心文档）
├── guides/                      # 操作指南
│   ├── CONTENT-EDITING-GUIDE.md
│   └── DEPLOYMENT-GUIDE.md
├── development/                 # 开发文档
│   └── SUBMODULE-SHARED-ADMIN.md
└── troubleshooting/             # 故障排查
    └── CLASS-NOT-FOUND-FIX.md
```

## 添加新文档

1. 在 `docs/` 根目录或合适的一级子目录中新建 `.md` 文件
2. 文件名即文档标题（导航中显示去掉 `.md` 后缀的文件名），建议使用描述性命名
3. 无需重启或改配置，刷新后台文档页即可看到

## 编写规范

- 首行为 `# 一级标题`，与文件名含义一致
- 使用 `##` / `###` 组织章节
- 代码块使用 ``` 围栏并标注语言（如 ` ```php `）
- 文末标注「最后更新」日期
- 译名遵循「不高兴汉化」版本，与站内词条保持一致

## 渲染说明

- 若运行环境加载了 `Parsedown`（见 `lib/Parsedown.php`），使用完整 Markdown 渲染
- 否则使用内置轻量渲染器，支持标题、加粗、行内代码、引用块、代码块与段落
