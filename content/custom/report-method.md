# 翻译方法与译名依据

> 本页记录本站中文翻译的整体机制、译名确定流程与质量校验规则。既是对读者的说明，也是后续所有翻译工作必须遵守的操作规范。
> 最近更新：2026-09-15

## 一、内容来源

- 英文基础内容全部来自 Hellboy 英文 Fandom 维基（<https://hellboy.fandom.com>）的快照，保存在站点 `content/pages_en/`。
- 该层为**只读冻结层**：任何翻译、清理、格式修复都不改动英文原文，保证随时可以与英文版逐字对照。
- 中文翻译另参考维基百科、地狱男爵吧、「不高兴汉化」译本以及各类中文网络资料；站长本人的读书笔记与简评保留在对应条目正文开头。

## 二、三层版本模型

每个条目在服务器上对应三个文件层，页面右上角用「中 / EN」切换：

| 层 | 目录 | 含义 |
| --- | --- | --- |
| EN 原文 | `content/pages_en/` | Fandom 英文快照，永不修改 |
| 标准中文版 | `content/pages/` | 站长手译或经逐条验证固化的译文，**优先保留，绝不被机翻覆盖** |
| 机翻中文版 | `content/pages_mt/` | AI 初翻稿，默认呈现，顶部有琥珀色「机译」提示条 |

呈现规则：

1. 中文模式下默认优先显示机译稿；没有机译稿时回退标准中文版。
2. 标准中文版可用 `?v=std` 查看；英文原文用 `?lang=en` 查看。
3. 机译稿经人工逐条校对后「固化」进标准层，状态由 `machine` 改为 `reviewed`。
4. 翻译状态（none / partial / machine / reviewed）集中记录在 `content/translation.json`。

## 三、译文体例规范

1. AI 译文一律为**纯中文**，不逐段附英文原文（站点本身有 EN 视图可对照）；站长手写的「一段中文一段原文」笔记保持原样不动。
2. 章节标题全部中文化：Story=生平/故事、History=历史、Synopsis=剧情简介、Physical appearance=外貌、Gallery=画廊、Trivia=趣闻、Notes=注释、References=参考资料 等。
3. Markdown 链接的 href（英文 permalink，如 `/entry/Hellboy_%28character%29`）**一个字符都不改**，只翻译链接的可见文字。
4. 图片的数量、顺序、src 不允许改动；画廊图片在源文件里以独立成行的裸文件名保存，由渲染层自动还原为网格与灯箱。
5. 期号（Issue #3）、ISBN、日期、URL、文件名不翻译。
6. 清理 Fandom 迁移残留：`<File:>`、`文件:`、`de:/sv:` 跨语言链接、`colspan` 导航残骸、重复加粗分类标签等。
7. 源站本身缺失的图片不造死链；源站本身指向不存在条目的链接，在固化阶段降级为纯文本。

## 四、角色译名的确定与交叉验证流程

这是本站最关键、争议最多的部分。角色名**不允许直接保留英文**，每个角色都必须有一个初翻中文译名（即使是冷门龙套），并标注置信度。

### 第 1 步：收集种子译名（已确立口径，强制沿用）

- 站长已经使用的中文条目名（如 特雷佛·布鲁姆、雅加婆婆、赫尔曼·冯·卡朗普特）。
- `content/glossary.json` 术语表中已确认的译名（如 Hellboy=地狱男爵、Abraham Sapien=亚伯·塞皮恩、Ogdru Hem=奥格德鲁·赫姆）。
- 「不高兴汉化」漫画译本中的通行译名。
- 种子译名只能沿用，不允许因为「另一个译法更常见」而擅自更改；确有异议时在术语表中挂 `pending` 待审，不直接改正文。

### 第 2 步：Fandom 核对身份

- 抓取 `https://hellboy.fandom.com/wiki/<条目名>`，确认角色的真实身份、登场作品、国籍 / 文化背景，避免把同名角色搞混（例如 Fandom 用 `(character)`、`(series)` 后缀区分角色页与系列页）。

### 第 3 步：中文互联网交叉验证

按角色类型选择译名来源，优先级从高到低：

1. **影视角色**：2004 / 2008 / 2019 三部电影的官方或通行中译（如 Nuada=努阿达、Sammael=萨麦尔、Mr. Wink=温克先生、Angel of Death=死亡天使）。
2. **漫画角色**：中文漫画译本、维基百科、百度百科、豆瓣、汉化组资料中能查到的通行译法。
3. **真实历史人物**：历史教科书 / 百科的通用中译（如 Adolf Hitler=阿道夫·希特勒、Heinrich Himmler=海因里希·希姆莱、Ota Benga=奥塔·本加）。
4. **神话 / 恶魔 / 传说人物**：先确认其文化来源（凯尔特、斯拉夫、埃及、希腊、北欧、印度、基督教恶魔学……），使用该神名在该文化中的**通用中文译法**，而不是按英文拼写硬音译（如 Dagda=达格达、Perun=佩伦、Krampus=坎卜斯、Astaroth=阿斯塔罗斯）。
5. **非英语来源的虚构人名**：按**源语言发音**音译，不按英语化读法：
   - 俄语名按俄语（Iosif Nichayko=约瑟夫·尼柴科）；
   - 德语名按德语（Raimund Diestel=赖蒙德·迪斯特尔）；
   - 西语名按西语（Cayetano=卡耶塔诺）；
   - 日语人名尽量还原汉字可能形式（Yumiko Daimio=大澄弓子），无法确认时给音译。
6. **完全查不到中文资料的冷门角色**：按发音给出合理的音译初翻名。
7. **绰号、称号、群体**用意译（The Golden Army=黄金军团、Butcher Guards=屠夫卫队、The Torch of Liberty=自由火炬）。

### 第 4 步：标注置信度

每个译名带一个置信度级别，写入译名研究数据与 `translation.json`：

- **high**：电影官方译名 / 多种中文资料一致 / 站长早已使用；
- **medium**：有中文佐证但来源较少，或存在不统一译法；
- **low**：纯按发音初翻、待人工验证。

### 第 5 步：落地与审核

- 译名写入两个位置：`translation.json` 的 `zh_title`（控制页面 H1、侧栏、卡片的中文显示名）与 `content/glossary.json`（术语表，后台可标 pending/confirmed 审核）。
- 正文首次出现采用「中文译名（English 原名）」格式，之后统一使用中文译名。
- low / medium 的译名以后可在后台术语表中逐条审核、一键统一，不需要改正文文件。

## 五、译名决策实录：那些举棋不定的名字

流程是冷的，译名是热的。总会遇到两个译名各有道理、怎么选都像亏欠了谁的情况。这一节不写规则，只如实记录站长本人在几个关键译名上的犹豫与取舍，以及最后拍板的标准——以后再遇到同类分歧，照这个尺度办。

**总原则（2026-09-15 拍板）**：一个条目存在多个译名时，必须挑**唯一一个**作为全站标准名；其他译法连同各自的来由，以「译名说明」写进该条目正文，而不是任由它们散落在不同页面、不同时期的译文里。读者查得到旧译，站点守得住统一。

### 1. The Crooked Man：《扭曲人》 vs 《驼背人》

- 《驼背人》是民间汉化组「不高兴汉化」漫画译本里的原译。本站翻译长期严格追随不高兴，于情于理都该沿用。
- 《扭曲人》是 2024 年真人电影上映之后，简体中文网络环境（百科、影评、字幕组、资讯通稿）里通用的电影名，市场已经铺开，属于「不接受也得接受」的局面。
- 当时的纠结：守旧译是对汉化前辈的尊重，用新译是对新读者的体贴。
- **最终标准名：《扭曲人》。** 理由很朴素——译名的第一职责，是让读者能用自己手里的词找到内容；看过电影找来的新读者，只会搜「扭曲人」。但旧译不抹掉：电影页、漫画故事页、角色页顶部都保留译名说明，注明「不高兴汉化旧译《驼背人》」及其来由。

### 2. Lobster Johnson：「大螯虾强生」 vs 「龙虾强生」

- 「龙虾强生」是简体中文网络的通译，语法上也更顺——lobster 就是龙虾，加个「螯」字看起来多此一举。
- 「大螯虾强生」我个人判断是不高兴本人的个人恶趣味：他并非不知道「龙虾强生」更通用，偏要加一个「螯」字。这个多余的字里，恰恰有民间翻译人独有的那份调皮与较真。
- 当时的纠结：想遵循白高兴（不高兴）的译本，有时候又很难放弃通用的语法和习惯。
- **最终标准名：「大螯虾强生」。** 这一条是情感压过了实用——我还是想坚持民间翻译人的情怀，追随不高兴。（字形提醒：是虫字旁的「**螯**」，虾钳之意，不要写成鱼字旁的「鳌」。）通译「龙虾强生」收进术语表别名，正文译名说明中也保留。

### 从这两个案子里沉淀下来的判断标准

1. 市场与新读者认知已经一边倒的**影视化名字** → 接受现实，用通译（扭曲人）。
2. 没有形成压倒性市场认知、而旧译又承载着汉化人个人风格的名字 → 追随不高兴，守情怀（大螯虾强生）。
3. 无论怎么选：标准名全站唯一；落选译法写进正文「译名说明」，理由讲清楚，不做静默替换。
4. 实在拿不准的（如 Ogdru Jahad / Ogdru Hem 神名译法，见第八节），术语表挂 `pending`，已发布的旧页面不强行翻烧饼，拍板后新条目按新口径走。

## 六、结构闸门（mt_gate）

每篇机译稿落盘前必须通过 `tools/mt_gate.py` 与英文源做 round-trip 结构比对：

1. Markdown 内链的 **href target 数量与顺序**必须与 EN 完全一致（中文调语序时容易把同句两个链接的顺序颠倒，需要改写句式对齐，绝不许改 href）；
2. 图片数量与每条 src 完全一致；
3. 标题层级序列一致；
4. 原生 HTML 表格数量一致；
5. 不允许残留翻译占位符或未还原的内部 token。

闸门只保护结构，不限制可见文字的翻译质量。

## 七、发布前回归

- 每轮批量翻译后做全站回归：全部条目 ×（机译 / 标准 / EN）三视图逐一请求，要求全部 HTTP 200、零 PHP Fatal、零模板标签泄漏、零 MediaWiki 残留。
- 移动端（390px）、平板、桌面（含 4K）抽样截图检查属性卡片与画廊。
- 改动渲染层（index.php / app.css / app.js）后用静态资源版本号 `?v=filemtime` 自动破浏览器缓存。
